# AmneziaWG Telegram Manager

Панель управления AmneziaWG 3+ через Telegram: клиенты, QR, конфиги,
блокировка, срок доступа, квоты и расписания. Модель ИИ и подписка не нужны.
Есть самостоятельный бот и адаптер для существующего OpenClaw.

**Статус: alpha.** Основа работает на личном VPS автора; универсальный
установщик проходит отдельную проверку. Это независимый проект,
не официальный продукт Amnezia. Не заявляем поддержку всех будущих AWG 3.x.

## Установка

Ubuntu 24.04, root/sudo, systemd, amd64 или arm64, доступ к GitHub,
nodejs.org, go.dev и Telegram. Создайте отдельного бота через @BotFather,
узнайте свой числовой Telegram ID и отправьте боту `/start`.

Одна команда запускает интерактивный мастер:

```bash
curl -fL https://raw.githubusercontent.com/digiden96/awg-telegram-manager/main/install.sh -o /tmp/awg-manager-install.sh && sudo bash /tmp/awg-manager-install.sh
```

Мастер скачивает текущий `main`. Для воспроизводимой установки используйте
проверенный commit/release и запускайте `sudo bash install.sh` из его checkout.

Мастер спросит:

1. Подключить существующий AWG или установить AWG 3.1 с нуля.
2. Конфиг/интерфейс либо подсеть и UDP-порт нового сервера.
3. Публичный IPv4/домен сервера и внешний порт.
4. Числовой ID владельца, токен бота (скрытый ввод), необязательный ID темы.
5. Режим `standalone` (по умолчанию) или `openclaw`.
6. Подтверждение показанных параметров.

Мастер устанавливает зависимости, проверяет токен, резервирует серверный
конфиг, импортирует пиры и включает службы. При установке с нуля собираются
AWG Go `v3.1.20260828` и tools `v3.1.20260812` по фиксированным commit SHA.
Если системный Node старше требуемой версии, Node 24 ставится в отдельный
каталог `/opt/awg-manager-node` с проверкой SHA256 скачанного архива.

Порт также нужно разрешить в firewall панели хостинга. Мастер добавляет
правило для активного UFW при новой установке. Сторонние firewall требуют
проверки администратором. Конфиги клиентов покрывают IPv4; IPv6 не туннелируется.

Повторная установка поверх базы менеджера отклоняется. Автоматическое
обновление и откат версий пока не реализованы.

## Telegram

Отправьте `/vpn` (в standalone также `/start`). Меню содержит список клиентов,
добавление, расписания и состояние. Карточка клиента показывает адрес,
handshake, трафик, срок и квоту. После создания сразу доступны QR и `.conf`.
Их можно пересылать владельцу устройства.

Кнопки работают без модели. Имя, дата, квота и cron ожидаются до 10 минут;
`отмена` отменяет ввод. Один ожидаемый ответ на Telegram ID, независимо от темы.
Доступ разрешён только одному владельцу в личном чате. Используйте отдельный
конфиг для каждого устройства. QR и конфиг содержат приватный ключ.

Квоты считают сумму RX+TX; проверка примерно каждые 10 секунд, возможен небольшой
перерасход. Счётчики AWG сбрасываются при рестарте интерфейса, поэтому это
приблизительный учёт, не биллинг. Дневные/месячные периоды и расписания сейчас
используют Europe/Moscow. Cron меняет ручное разрешение доступа; срок и квота
продолжают ограничивать клиента. Пропущенные во время остановки cron-события
не воспроизводятся.

## Импорт существующего AWG

Поддерживается host-интерфейс, доступный через `awg`, конфиг с `[Interface]`
и `[Peer]`, один IPv4 `/32` на каждого пира в подсети сервера. `SaveConfig=true`,
IPv6, дополнительные peer-параметры и несколько AllowedIPs отклоняются.
Docker-контейнеры и другие управляющие панели пока не поддерживаются.
После импорта менеджер становится единственным владельцем peer-секций:
не редактируйте их параллельно через другую панель.

Серверный конфиг не содержит клиентских приватных ключей. Импортированные
пиры сохраняют подключение и получают управление доступом, но экспорт QR
недоступен. Кнопка перевыпуска с подтверждением создаёт новые ключи и отзывает
старый конфиг. Для собственных пиров менеджер хранит ключи в root-only SQLite.

## OpenClaw

Адаптер рассчитан на проверенную структуру установки: пользователь `openclaw`,
`/var/lib/openclaw/.openclaw/openclaw.json`, команда
`/var/lib/openclaw/runtime/bin/openclaw`, служба `openclaw`.
API плагина проверялся с OpenClaw 2026.9.2. Другие схемы установки требуют
ручного подключения адаптера.

Мастер сохраняет предыдущий конфиг, задаёт owner-only Telegram-доступ,
отключает создание/переименование тем и добавляет плагин. Не используйте
один токен одновременно для standalone polling и OpenClaw. Существующий
другой плагин `/vpn` нужно предварительно отключить.

## Данные и диагностика

- `/etc/awg-manager/config.json`: endpoint, пути и интерфейс (root-only).
- `/etc/awg-manager/telegram-token`: токен, доступен только root и группе бота.
- `/var/lib/awg-manager`: SQLite, ключи, политики.
- `/var/lib/awg-telegram-bot`: ожидание ввода и offset standalone-бота.
- `/var/backups/awg-telegram-manager`: исходный конфиг перед импортом.

```bash
sudo systemctl status awg-manager awg-telegram-bot
sudo journalctl -u awg-manager -u awg-telegram-bot -n 100 --no-pager
sudo awg-manager list
```

Standalone-бот работает непривилегированно и вызывает ограниченный root-helper
через sudo. Не давайте пользователю бота право менять установленный код или
sudoers. Демон политик должен иметь возможность менять конфиг и сетевой интерфейс.

Перед обновлением сохраняйте конфиг, `/etc/awg-manager` и базу SQLite через
SQLite backup API или при остановленном менеджере. Чтобы вернуться к исходному
конфигу, остановите менеджер и бота, восстановите конфиг из резервной копии и
перезапустите соответствующий AWG-интерфейс. Это разорвёт активные соединения.

## Разработка

```bash
python3 -m unittest discover -s tests -p 'test_*.py' -v
node --check openclaw-plugin/index.mjs
node --check telegram-bot/bot.mjs
bash -n install.sh
```

Тесты backend запускаются на Linux в временной базе без реального VPN.
`tests/plugin-smoke.mjs` предназначен для настроенного тестового хоста.
План развития: [ROADMAP.md](ROADMAP.md). О проблемах сообщайте без токенов,
приватных ключей и QR: [SECURITY.md](SECURITY.md).
